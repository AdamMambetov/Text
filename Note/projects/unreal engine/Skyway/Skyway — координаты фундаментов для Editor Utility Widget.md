## Задача пользователя

  

В UE5-проекте есть механика строительства в духе Rust. Два типа фундамента:

  

- квадратный, 200 см;

- треугольный **равносторонний**, сторона 200 см.

  

Нужен Editor Utility Widget, который удобно показывает координаты мест, где можно

построить фундамент. Координаты — двумерные (только X, Y). Проблема возникает

именно на треугольниках: как их отображать?

  

Уточнения по ходу:

  

- координаты нужны **только для отображения** (список/миникарта), не как ключ

валидации размещения;

- пользователь возразил: «в Rust и в этом проекте треугольники сверху выглядят

одинаково» — то есть мой тезис о прямоугольном треугольнике в Rust требует проверки.

## Ключевой вывод: общей решётки для квадрата и равностороннего треугольника не существует

  

- Квадрат 200×200 живёт на решётке `(200·i, 200·j)`.

- Равносторонний треугольник со стороной 200 имеет высоту `h = 200·√3/2 = 173.205`,

его строки идут с шагом **86.6025**, а нечётные сдвинуты по X на 100.

- Отношение `200 / 86.6025 = 4/√3` — **иррациональное** → общей целочисленной

решётки не существует в принципе. Любая попытка свести оба типа к одному

`int`-номеру клетки даёт либо дробные координаты, либо коллизии.

  

Дополнительное следствие: площадь треугольника 17320.5, квадрата 40000,

`40000/17320.5 = 2.309` — **сплошной пол из квадратов 200 + равносторонних

треугольников 200 собрать нельзя**. Сетка доступных клеток всё равно не будет

прямоугольной маской, поэтому хранить её надо как `TSet` ключей.

## Предложенные форматы координат (два уровня)

  

Уровень 1 — машинный ключ клетки (int), уровень 2 — мировые XY (float) для подписи.

Не смешивать.

  

### Квадрат (шаг 200)

  

```cpp

FIntPoint Key = { FMath::RoundToInt(X / 200.f), FMath::RoundToInt(Y / 200.f) };

// центр клетки: (200*Key.X, 200*Key.Y)

```

  

### Треугольник — осевая решётка A2

  

Базис `e1 = (200, 0)`, `e2 = (100, 173.205)`:

  

```cpp

constexpr float A = 200.f;

constexpr float H = A * 0.8660254f; // 173.20508

  

// Ключ: (U, V, Facing), Facing ∈ {▲, ▼}

// ▲ (U,V): вершины P, P+e1, P+e2

// ▼ (U,V): вершины P+e1, P+e2, P+e1+e2

// P(U,V) = (A*U + A/2*V, H*V)

```

  

Обратное преобразование из мировых XY (пивот в центре тяжести,

`h/3 = 57.735` от основания, `R = 115.47` для ▼):

  

```cpp

for (uint8 Facing : {0u, 1u}) {

float Y0 = Y - (Facing ? 115.4701f : 57.7350f);

int32 V = FMath::RoundToInt(Y0 / H);

int32 U = FMath::RoundToInt((X - A*0.5f*V) / A);

FVector2D P(A*U + A*0.5f*V, H*V);

// проверить попадание центра в нужный треугольник с допуском ~1 см

}

```

  

`Facing` — то «третье измерение», которого не хватает в 2D-выводе; без него

▲ и ▼ на одном основании считаются одной клеткой.

  

### Правила отображения в виджете

  

1. В списке — строка вида `TR 3, 5, ▲` и `SQ 3, 5`, рядом мировые метры

`(X 700.0, Y 866.0)`. Сортировка по `(V, U, Facing)`.

2. **Не показывать сырые 86.6025 / 173.205 как координату** — выглядит как баг.

Показывать целые `(u, v)`, сантиметры — в тултипе, с одной цифрой после запятой.

3. При отрисовке фигур на canvas — одинаковый Scale по обеим осям; линии сетки по Y

с шагом 86.6 и сдвигом 100 на нечётных строках.

4. Единый машинный ключ (если понадобится) — биты, integer math, без float:

`[1 bit Facing][21 bit U + offset][21 bit V + offset][1 bit Type]`.

## Про Rust: честная оговорка

  

Тезис о том, что в Rust треугольный пол — **прямоугольный** (половина квадратного

пола 3×3 м, катеты 3 м, гипотенуза ~4.24 м, два треугольника дают ровно квадрат),

взят из общих знаний о системе строительства Rust, **а не из этого проекта**.

Возражение пользователя («сверху выглядит одинаково с этим проектом») — весомый

аргумент, который надо проверять измерением, а не памятью.

### Наблюдения по числам в `SM_Foundation_Triangle_01.uasset`

  

| Значение | Ожидается для равностороннего 200 | Найдено |

|---|---|---|

| 1.7320508 (высота) | да | **0** |

| 1.1547005 (радиус описанной окружности) | да | **0** |

| 0.5773503 (радиус вписанной) | да | **0** |

| 0.8660254 (половина высоты) | да | **0** |

| 2.8284271 (гипотенуза катетов 2.0) | нет | 1 (возможно случайность) |

| 1.0 / 2.0 | — | 52 / 21 |

  

**Интерпретация:** ассет полон точных ±1.0 и ±2.0 и не содержит ни одного числа,

характерного для равностороннего треугольника. Это больше похоже на треугольник,

вписывающийся в бокс 2×2 (катеты по осям), то есть на «половину квадрата» как в Rust.

**Это гипотеза, не доказательство:** те же числа могли попасть из bounds или квот,

а вершины хранятся в Nanite-контейнере с Oodle-сжатием, недоступным для разбора.

  

### Как проверить за 15 секунд в редакторе

  

1. Открыть `SM_Foundation_Triangle_01` и посмотреть **Bounds** в Details:

- Size ≈ **200×200×30** → треугольник прямоугольный (половина квадрата);

- Size ≈ **200×173×30** → равносторонний.

2. Либо поставить два треугольных фундамента вплотную: получается ровно

квадрат 200×200 → прямоугольный.

3. Заодно уточнить пивот меша (центр тяжести / центр описанной окружности /

вершина) — от него зависят смещения в формулах.

## Два варианта решения (зависит от результата проверки)

  

### Вариант A — треугольник половиной квадрата (как в Rust)

  

Проблема исчезает, общая решётка 200×200:

  

```

SQ (i, j) → ■

TR (i, j, corner) corner ∈ {NW, NE, SW, SE} → ▨

```

  

`i = round(X/200)`, `j = round(Y/200)`. Сортировка по `(j, i, corner)`.

  

### Вариант B — треугольник действительно равносторонний

  

Общей целочисленной решётки с квадратом не будет никогда, поэтому показываем

это явно:

  

```

SQ (i, j) шаг 200

TR (u, v, ▲/▼) решётка A2: e1=(200,0), e2=(100,173.205)

```

  

В списке — целые `(u, v)`, реальные метры отдельной колонкой.
